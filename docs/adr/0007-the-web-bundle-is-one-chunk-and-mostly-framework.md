# ADR-0007 — the web bundle is one chunk, and it is mostly framework

**Status:** accepted · 2026-09-16

## Context

`/app` scores 65 on Lighthouse performance. The cause is not a slow API — that
was measured and fixed (`/v1/grid/now` went from ~8.5s to ~450ms at origin and
LCP moved 5.6s → 5.7s, which is how we learned it was not the API). The
waterfall shows the first API call starting at 4,009ms: the page is bundle-bound,
not data-bound.

This ADR exists because that bundle has now been reasoned about twice from
guesses, and both guesses were wrong. It records what it actually contains, so
the next person argues with numbers.

### Two earlier conclusions, corrected

1. **"`react-native-reanimated` is the big one."** It is imported by exactly one
   component (`thinking-orb.tsx`), and it is **not in the web bundle at all** —
   `grep` finds zero occurrences of `reanimated` or `Worklets`. So are
   `react-native-gesture-handler`, `expo-haptics`, `expo-web-browser` and
   `expo-font`: declared dependencies with no source imports and no bundle
   presence.

2. **"Code splitting is impossible under `web.output: "static"`."** Too broad,
   and the important correction. `asyncRoutes` genuinely does nothing here —
   that part holds. But a **manual `import()` does split.** Probed directly: a
   module imported dynamically and statically nowhere else was emitted as its
   own 206-byte chunk, and its marker was absent from the main bundle.
   Splitting is therefore available; it simply has to be asked for by hand.

## The measurement

1,933,501 bytes raw, 547,549 gzipped, in a single `entry-*.js`. Attributed to
source files by decoding the sourcemap's own mappings (`--source-maps`), so this
is generated bytes per module, not source size:

| area | bytes | share |
| --- | ---: | ---: |
| `expo-router` | 436,465 | 24% |
| `react-native-web` | 282,337 | 15% |
| `react-dom` | 178,881 | 10% |
| other `node_modules` | 220,817 | 12% |
| app code | 718,972 | 39% |

**Framework is 49% of the bundle** and none of it is deferrable: it is what
renders the first pixel. That is the ceiling on what any splitting can achieve.

### What each page carries and never runs

`src/components/landing` imports nothing from `components/charts`,
`components/app`, `lib/geo`, `components/voice` or `lib/voice` — verified, not
assumed. So the indexed pages carry, download and parse:

| dead on landing | bytes |
| --- | ---: |
| `src/components/app` | 100,570 |
| `src/components/charts` | 72,568 |
| `src/app/app` (the four screens) | 68,816 |
| voice (`lib/` + `components/`) | 54,111 |
| `src/lib/geo` (Brazil geometry) | 34,286 |
| **total** | **330,351 — 18%** |

and `/app` carries 86,095 bytes of landing components it never renders.

## Decision

**Record the numbers; change nothing yet.** The two ways to spend this 18% are
both architectural, and both are the product owner's call rather than a
refactor:

- **Split the `/app` subtree behind a manual `import()`.** Cuts ~18% from the
  SEO-critical pages, which is where a Lighthouse score has to be earned —
  `/app` is `noindex`. The cost is a `Suspense` boundary inside a **prerendered**
  route: `/app` ships full HTML today, and a lazy boundary that has not resolved
  by hydration renders a fallback instead, which React treats as a mismatch and
  recovers from by discarding the server HTML. On a screen carrying live orders
  that is not a change to make speculatively.
- **Leave it.** `/app` is `noindex` and behind a login; its readers are
  operators with warm caches, not crawlers.

The one thing explicitly **not** worth doing: deferring the voice session
machinery. Only the modules that load on activation can move — instructions,
execute, tools, session, the audio backend and codec — and they total 28,554
bytes, 1.5% of the bundle, in exchange for a `Suspense` boundary on the critical
path of the feature. Bad trade, and it is recorded here so it is not proposed
again.

## Consequences

The attribution above is reproducible: `expo export --platform web
--source-maps`, then decode `mappings` and sum each segment's generated span
against its source. Re-run it before claiming anything about this bundle.

Dependencies with no source imports (`react-native-gesture-handler`,
`react-native-worklets`, `expo-haptics`, `expo-web-browser`, `expo-font`) are
left in `package.json` deliberately — they are Expo peer requirements pulled by
`expo-router` and friends, and removing them costs nothing in bundle bytes
because they are already absent from it.
