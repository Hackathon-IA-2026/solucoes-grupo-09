# Working in this repository

## Reporting to the user — read this first

**Be concise. Default to a few lines.** The user has asked for this explicitly
and more than once. Long status reports are unwanted, including when a lot of
work was done.

- Lead with the answer or the outcome. No preamble, no recap of what you were
  asked, no restating what you already said in an earlier message.
- Prefer a short table or a few bullets over prose. One screen, not five.
- Report a result, not a narrative of how you got there. The commit message and
  the ticket are where reasoning belongs — that is what they are for.
- Do not re-explain a finding the user has already been told.
- Only expand when the user asks for detail, or when a decision genuinely needs
  their input — and then give them the decision, not the whole investigation.
- No progress commentary while working. Report when something is done or
  actually blocked.

The rigour belongs in the work, the commits and the tickets. Not in the chat.
